# Спільний погодинний час: Europe/Kyiv та UTC

Остаточні рішення авторки проєкту зафіксовано 01.11.2026.

Стан збереження: код, правила й документація підготовлені для GitHub. Готовий знімок
перевірено та збережено окремим архівом. Стиснені файли таблиці ще не перенесені
до main; описаний нижче current.json належить повному комплекту цього архіву.

Усі погодинні таблиці використовують одну схему. Інтервали будуються між місцевими
півночами в `Europe/Kyiv` шляхом перебору UTC. Кожен визначений інтервал триває одну
реальну годину. Звичайна доба має 24 інтервали, весняна 23, осіння 25.

| Випадок | Підпис `hour` |
|---|---|
| Звичайна година | `02:00-03:00` |
| Весняне переведення | `02:00-04:00` |
| Перша осіння година | `03:00-03:00` |
| Друга осіння година | `03:00-04:00` |

Підписи слугують для показу. Ключ торгівлі: `energy_system`, `country`,
`customs_regime`, `start_utc`. Відключення зіставляються за тим самим `start_utc`.
Місцевий підпис без зміщення UTC не є достатнім ключем.

## Політика джерел

Авторка обрала ENTSO-E еталоном для звірки імпорту/експорту, оскільки в цьому
дослідженні спирається на нього як на першоджерело даних Energy Map. Це рішення
про метод перевірки, а не твердження, що кожний запис будь-якого джерела правильний.
Після уточнення обмежень публікації остаточно вирішено: обсяги у публічній таблиці
залишаються з Energy Map. Розбіжності позначаються, без підстановки значень ENTSO-E.

Приватними залишаються XML, токени, числові витяги й детальні результати зовнішньої
звірки. Публічний комплект не містить детального реєстру зовнішніх збігів/розбіжностей
за датами й напрямками. Він залишається у приватному архіві.
Зовнішня звірка охоплювала п'ять експортних напрямків за жовтень 2021 та доступну
вибірку перехідних діб. Вся історія не вважається зовнішньо перевіреною.

## Очищення

`data/hourly_trade/rules.json` містить точні 212 правил, погоджені авторкою:

- 150 зайвих нулів `03:00-04:00` у п'яти експортних напрямках за 01-30.10.2021,
  включно з Румунією 19.10.2021. З кожної повтореної пари вилучається лише один
  нуль. 31 жовтня обидві реальні години зберігаються.
- 62 нульові заглушки `03:00-04:00` у конкретних старих весняних добах 2020-2024.
  Для 42 була доступна зовнішня часова звірка. Для решти 20 авторка погодила
  застосувати той самий структурний шаблон як явне припущення. Це зазначено
  в журналі вилучень та `calendar_mapping_basis` для збережених рядків цих діб.

Кожне правило перевіряє дату, зону, країну, режим, підпис, кількість записів доби
та повтореної позначки, наявність нуля. Ні нуль сам по собі, ні точний дублікат,
ні повтор години не є загальним правилом видалення. Обсяги решти записів і добові
суми за напрямками мають залишатися незмінними. На нові дати ці видалення
автоматично не поширюються.

## Невизначений час

Для 69 старих осінніх комбінацій дата/напрямок із 24 записами визначаються
23 однозначні години. Єдиний запис `03:00-04:00` зберігається без UTC, бо неможливо
однозначно встановити, яку з двох осінніх годин або яке їх представлення він означає.
Всі 24 записи залишаються; доба позначена неповною для погодинного аналізу.
Обсяг не дублюється, не ділиться, відсутня година не створюється.

Якщо присутні обидва осінні записи з однаковими старими підписами, їхній порядок
трактується як порядок реальних годин. Це припущення має статус
`source_order_assumption`; воно не підтверджене постачальником.
При перестановці рядків оновленого файлу зіставлення незмінної історії відновлюється
за прийнятим порядком та значеннями, щоб обсяги не помінялися місцями між UTC-годинами.
Точні однакові повтори зіставляються з урахуванням кратності.

## Поля готової таблиці

| Поле | Зміст |
|---|---|
| `date` | Місцева дата початку інтервалу, YYYY-MM-DD |
| `hour_original` | Початкова текстова позначка Energy Map |
| `hour` | Узгоджений підпис; для спірного запису збережений вихідний |
| `energy_system` | Торгова зона, без об'єднання історичних зон |
| `country` | Напрямок із джерела; Білорусь-0.4-110 зберігається окремо |
| `customs_regime` | `імпорт` або `експорт` |
| `amount` | Обсяг Energy Map, МВт·год |
| `source_row` | Номер запису від нуля у вхідному CSV без заголовка; див. `input.csv.gz` |
| `start_utc`, `end_utc` | ISO 8601 межі UTC; порожні для невизначеного часу |
| `start_local`, `end_local` | ISO 8601 місцеві межі зі зміщенням UTC |
| `time_status` | Спосіб визначення часу, див. нижче |
| `calendar_complete` | Чи має дата/напрямок повний погодинний календар |
| `calendar_mapping_basis` | Чи застосовано погоджене припущення до весняної доби |
| `external_check_status` | Стале `private_comparison_not_published`: деталізація зовнішньої звірки приватна |

Статуси часу:

- `calendar_matched`: календар узгоджений; це не підтвердження обсягу.
- `source_order_assumption`: обидві осінні години визначені за прийнятим порядком.
- `calendar_matched_partial_day`: час цього запису визначений, але доба неповна.
- `ambiguous_fall_single`: осінній запис збережений без однозначного UTC.
- `unresolved_calendar`: невідомий шаблон; публікація з таким статусом блокується.

Статус приватності не підтверджує правильність обсягу. Відсутність зовнішнього
часового ряду не означає нульовий обмін.

## Де збережені результати

Покажчик `data/hourly_trade/current.json` визначає один завершений каталог
`snapshots/<version>/`. Його вміст:

- `trade.csv.gz`: готова таблиця; читається `pandas.read_csv` без розпакування.
- `input.csv.gz`: точні байти вхідного CSV, стиснені gzip; після розпакування
  SHA-256 збігається з `source_sha256` у поточному стані.
- `source.csv.gz`: шість полів прийнятої історії в зафіксованому порядку для наступного
  зіставлення. Це семантичний реєстр, його порядок може відрізнятися від нового input.
- `removed_rows.csv`: вилучені рядки Energy Map, вихідні номери, причини й підстави.
- `unresolved_time.csv`: збережені записи без однозначного UTC.
- `incomplete_days.csv`: неповні дати/напрямки для фільтрації погодинного аналізу.
- `audit.json`: обсяги обробки, статуси, перевірки, обмеження.
- `changes.json`: результати порівняння прийнятої історії та нових дат.

Формат gzip зменшує передачу файлів. Python читає його автоматично. Для Power BI
можна локально розпакувати CSV; програмно змінювати часові зміщення при імпорті не слід.

## Оновлення без API

```bash
python -m scripts.prepare_hourly_trade /path/to/new_energy_map.csv
python -m unittest discover -s tests -v
```

Для першого запуску без прийнятої історії дозволено лише перевірений файл за
SHA-256. Подальші оновлення порівнюються зі збереженим реєстром, а не лише з хешем
усього файлу. Однаковий SHA дозволяє перевірити цілісність готового знімка й пропустити
непотрібний перерахунок.

Прийнята історія — **всі сирі записи попереднього успішного знімка**, від мінімальної
до максимальної дати включно, з нулями, повторами й невизначеним часом. Спочатку
це 01.07.2019-30.06.2026. Після успішного додавання нові дати теж захищені.
Цей статус не означає, що всі обсяги перевірено через ENTSO-E.

Порівняння незалежне від порядку рядків: перевіряються мультимножини всіх шести
полів із кратністю однакових записів. Зміна значення за тим самим ключем позначається
як зміна, а також як вилучення старого й додавання нового представлення. Додавання
історичного запису, його вилучення, зміна обсягу/позначки/напрямку блокують оновлення.
Деталі відмови містять лічильники та до 1000 прикладів; обрізання явно позначається.
Старі виправлення не переносяться на змінену історію.

Нові дати повинні йти після останньої прийнятої дати без пропущених діб, мати повні
відомі календарі й ті самі активні напрямки, що остання прийнята доба. Нові країни,
зони, комбінації напрямків, невідомі структури, відсутні поля, від'ємні/нечислові
обсяги, неповні доби та повторені UTC-ключі потребують ручної перевірки.
Зміна охоплення торгівлі може бути реальною, але автоматично за звичайне оновлення
її не приймаємо. Числовий стрибок сам по собі без зовнішнього доказу не виправляється.

Спочатку всі результати записуються й перевіряються у тимчасовому каталозі.
Завершений незмінний каталог знімка зберігається окремо, а `current.json`
перемикається однією атомарною операцією. При відмові останній коректний покажчик
та його таблиця залишаються доступними. Незавершені файли ніколи не є поточними.
Одночасні запуски підготовки в один каталог не підтримуються; запускати послідовно.
Окремого розкладу/API-збирача для торгівлі не додано.

## Приватна зовнішня звірка

`scripts/entsoe_hourly_check.py` не звертається до мережі. A03 розгортається вперед
у межах свого Period; до першої точки значення не вигадуються. A01 не заповнюється.
Періоди, одиниці, крок і ключі перевіряються. Значення MW за одну фізичну годину
чисельно дорівнює MWh; для іншого кроку ця рівність не застосовується.
Приватна звірка й дозволений набір Energy Map мають зберігатися окремо.
